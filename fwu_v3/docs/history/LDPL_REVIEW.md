# LDPL 재검토 결과 — 2026-11-17

기준: `joo001121-create/FWU-logic`, `jh`, 커밋 `0e0a374d983bf194220e75da79b28598673bc0fa`.

13개 블록을 검토했고, 제어 코드는 **PICV Feedback 한 파일만 수정했다.** 나머지 12개는 기준 커밋과 바이트 단위로 같다. 주석·상수·제어 정책도 바꾸지 않았다. 모든 XML과 블록 등록 순서도 유지했다.

이번 결과는 **장비 연결 전 수정안**이다. LDPL 안내서와 기존 코드 대조, 정적 검사, 모의시험을 수행했다. 실제 DDC에서 컴파일·실행하거나 RS485 통신을 시험한 결과는 아니다.

## 1. 확인된 문제와 수정

기존 PICV Feedback은 별도 수신 프로그램이 `Input_OK`와 `Sample_Seq`를 기록한다고 가정했다. 그러나 그 프로그램은 없었고, LDPL v27에서 Modbus 응답 완료 이벤트를 받아 순번을 만드는 기능도 확인하지 못했다. VP만 추가해 놓아서는 이 기능이 동작하지 않는다. 이전 구현에서 이 외부 의존성을 해결하지 못한 것이 문제였다.

수정안은 DDC에 일반 Modbus 관제점을 등록하고, 기존 팬·ATS 코드에서 사용하는 `READPOINT_ALARM`과 `READPOINT`로 상태와 값을 읽는다. 별도 어댑터나 사용자 정의 함수는 필요하지 않다.

| 구분 | 수정안 |
|---|---|
| 실제 입력 | 밸브마다 개도·유량·냉수 출구 온도 3점, 총 12개 Modbus 입력점 |
| 읽기 허용 | `VP_FWU_PICV_Input_Enable=1`이고 해당 밸브의 세 입력점 알람 값이 모두 0 |
| 표시값 | 읽은 값을 기존 Position/Flow/Temperature VP에 기록. 기존 표시용 VP 이름은 유지 |
| 개도 유효성 | 기존처럼 0~100% 범위만 사용 |
| 입력 이상 | Feedback_Valid=0, 개별 Comm_Fault/Alarm=1, 전체 All_Closed=0 |
| 정상 정지 | 네 밸브 모두 유효하고 각각 5% 미만일 때만 닫힘 인정. 기존 SF Control 유지 |
| 동작 진단 | 위치 모드의 30%p 이상 편차·40초 초과 조건과 선택적 유량 검사 유지 |
| 통신 이상 검출 시간 | DDC 통신 경보 설정에 따름. 기존 Seq 기반 10초 판정은 사용하지 않음 |
| 정상값이 계속 같은 경우 | 값이 같다는 이유로 통신 불량을 만들지 않음 |

알람 값 8은 통신 경보다. 수정안은 8뿐 아니라 0이 아닌 입력점 알람을 모두 사용 불가로 본다. 이 때문에 `Comm_Fault`는 단선만을 뜻하지 않는다. 미사용 설정, 입력점 경보, 개도 범위 오류를 포함한 기존의 넓은 의미를 유지한다.

세 입력 중 하나만 이상이어도 해당 밸브의 입력 묶음을 무효화한다. 따라서 온도점만 이상이어도 정상 정지의 닫힘 확인은 대기할 수 있다. 입력 묶음이 정상일 때만 사용하는 구조를 유지했으며, 정지 조건을 새로 완화하지 않았다. 비상·원격 정지는 기존 우선순위로 계속 동작한다.

`Input_OK` 4개, `Sample_Seq` 4개, `Sample_Prev` 4개, `Input_Timeout` 1개는 코드에서 더 이상 읽거나 쓰지 않는다. 기존 XML의 ID와 외부 참조를 불필요하게 바꾸지 않도록 정의는 남겼다. HMI에는 사용 설정으로 노출하지 않고, 이 값들을 채워 주는 로직도 만들지 않는다.

## 4. 어렵거나 확인이 필요한 부분 — 완료로 처리하지 않음

### A. 매번 새 응답을 받았다는 별도 보증

LDPL v27만으로는 ‘현재 숫자가 이번에 새로 수신된 값인가’를 독립적으로 확인하는 단순한 방법을 찾지 못했다. 수정안은 DDC 통신 상태를 신뢰한다. 정상 운전 중 동일한 값이 계속 들어오는 경우와, DDC가 예전 값을 보관하면서 정상으로 표시하는 경우를 코드만으로 구별하지 못한다. 개도·유량·온도가 같은 수신 묶음인지도 보증하지 않는다.

특히 전원 재투입 후 **첫 응답 전 알람 값이 0이고 개도 초기값도 0이면 닫힘으로 판정할 수 있다.** Input_Enable=0인 동안은 막지만, 설정이 1로 저장된 채 재부팅하는 상황까지 그것만으로 해결되지는 않는다.

회사 PC/실기에서 첫 응답 전 상태와 통신 단절 시 경보 발생 시간을 확인해야 한다. 그 동작이 충분하다면 지금처럼 DDC 통신 상태를 사용하는 간단한 방식을 유지할 수 있다. 충분하지 않다면 엄격한 최신 수신 보증을 이번 v2 범위에서 제외할지, 제조사에서 제공하는 별도 수신 상태를 연결할지 결정해야 한다. **후자가 가능하다고 가정해 코드를 추가하지 않았다.** 임의 지연시간만으로 첫 응답을 받았다고 간주하지도 않았다.

### B. SF Control의 LOOP2 ID

p.81에는 같은 제어 관제점에 같은 loop_id를 배정한다고 적혀 있다. 현재 SF Control은 같은 `VP_FWU_SF_Speed_Value`에 모드별 ID 1~4를 쓰며, 이 방식은 기존 v1에도 있다. 모드는 서로 배타적으로 실행되고 기존 초기화 코드를 유지한다. 그렇더라도 안내서 문구와 완전히 일치한다고 판정할 수는 없다.

문서 차이만으로 누적 제어 상태까지 바꾸면 기존 운전 특성에 영향을 줄 수 있어 이번에는 고치지 않았다. 실기에서 모드 전환·LOOP2_INIT 동작을 확인한다. 엔진이 같은 출력에 여러 ID를 허용하지 않는다면 **SF Control도 수정 대상**이다. 함수 사용 가능 여부와 PI 전환 동작 검증은 구분해야 한다.

### C. 일반 DDC 설정이 필요한 부분

CH3 PICV 12점의 실제 주소·자료형·배율은 아직 없다. `PICV_POINT_MAPPING.csv`는 등록할 이름과 단위를 정리한 목록이며, 가져오기가 끝난 통신 설정 파일이 아니다. 확인하지 않은 레지스터 주소를 넣지 않았다. 같은 이름의 VP를 만드는 것으로 대체하면 통신 상태를 읽을 수 없다.

기존 XML에는 팬 CH1/CH2 배치, ATS CH3 배치, 옛 AO 배율이 남아 있다. 사용자 확인 구성인 팬 CH1·ATS CH2·PICV CH3에 맞게 엔지니어링 도구에서 정리해야 한다. 누수 입력도 실제 DI 등록이 필요하다. 이는 수신 어댑터 개발과 다른 작업이다.

냉수 공급 조건 VP와 선택적 유량 진단은 기존 보류 상태를 유지했다. 실제 조건의 공급 주체·밸브 유량 기준이 정해지기 전에는 Flow_Check_Enable=0을 유지한다. 단선과 전원 상실의 원인 구분, 신형 팬 계수, AO3 신호 범위는 기존 확인 항목을 유지했다.

## 5. 검증 결과

- 제어 코드 13개 구문 분석, XML 15개 파싱, 관제점 이름/ID 중복과 기존 이름 변경표 일치 확인.
- 타이머 번호 0~9와 블록 내부 중복 여부, 기존 API 종류·인수 개수 확인.
- 기준 커밋 대비 PICV Feedback만 변경, 나머지 12개 바이트 동일 확인.
- 모의시험 38개 통과. 통신 경보·복구, 밸브별 독립 판정, 0/5/100% 경계, 선택적 유량 진단, 정상 정지 대기와 원격 정지, 기존 알람·HB·Failover 포함.
- 미등록 참조를 숨기지 않음: 신규 PICV 실제 입력 12개와 기존 누수 입력 1개. 시험에서는 이 입력들을 명시적으로 모사했다.
- DDC 첫 응답 이전 상태, 실제 통신 시간, PI 응답·모드 전환, 전원 복구·이중화 절체, HMI/BMS 및 배선은 미검증.

시험 코드의 초기 통신 알람 8은 **시험 조건**이다. 실제 펌웨어가 그렇게 초기화된다는 근거로 사용하면 안 된다. 모의 LOOP2는 실제 PI를 계산하지 않으며, SECTIMER도 시험용 구현이다.

## 6. PC에서 이어서 할 일

1. `PICV_POINT_MAPPING.csv`에 실제 밸브 주소·레지스터·자료형·환산값을 채우고 DDC Modbus 관제점으로 등록한다. 누수 DI와 신형 팬/ATS 포트도 연결한다.
2. 엔지니어링 도구에서 13개 블록을 열고 구문/실행 검사를 한다. 기존 등록 순서를 유지한다.
3. 밸브 미연결 기동 → 첫 통신 성공 → 선 분리 → 통신 복구 → 전원 재투입을 시험한다. 초기 0과 실제 닫힘 0을 구별할 수 있는지 확인한다.
4. 정상 정지 때 4개 밸브의 개도가 모두 5% 미만일 때만 팬 정지하는지, 입력 불명 상태에서도 비상·원격 정지는 적용되는지 확인한다.
5. 팬 5개 모드 전환, PI 초기화, 통신 고장 시 AO 전환, 기존 보호·알람 시나리오를 시험한다. 팬·밸브 정수는 해당 개발팀 확인값을 적용한다.

기존 합의 중 기능을 더 삭제하거나 운전 정책을 바꾸는 결정은 이번에 하지 않았다. 위 A/B는 남은 판단 항목이며, 실기 결과 없이 ‘모두 지원 확인 완료’로 표시하지 않는다.
