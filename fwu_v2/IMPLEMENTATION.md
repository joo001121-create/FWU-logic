## 연계 변경

- 기존 Alarm-2의 8개 외부 센서 판정을 제거하고 종류별 10개 블록으로 옮겼다. Alarm-2에는 누수·필터를 유지했다.
- Alarm-1의 단일 PICV 편차/유량 검사를 제거하고 PICV Feedback으로 옮겼다. 위치 모드에서만 명령-개도 비교를 허용한다. 실제 모드와 유량 기준 미확정 상태는 별도 표시한다.
- Alarm-3의 옛 단일 유량계 감시를 제거했다. 새 네 밸브 수신 상태로 기존 Flow Comm Fault를 집계한다.
- Remote Shutdown과 Failover는 변수명·타이머 상수·주석을 정리했고 실행 분기와 쓰기 우선순위는 유지했다.
- 누수/필터 결과 VP 2개를 추가해 기존 미정의 결과점을 보완했다. 누수 DI의 실제 주소는 만들지 않았다.
- 5개 보조 블록을 DDC에 등록했다. 각 블록 타이머는 0~9 이내이며, 새 입력 상태가 주 제어에 반영되도록 앞에 배치했다.
- 물리 IO·Modbus 및 외부 서비스 맵은 복사본 그대로다. 새 하드웨어 배치로 완성됐다는 의미가 아니다.

## 검증 결과와 한계

Python 구문, XML 파싱, 관제점 이름/ID 중복, DDC 로직 등록, Timer/LOOP2 번호와 참조를 검사했다. 새 미정의 참조는 없으며, 기존 `FWU_LEAK DETECT`는 여전히 연결되지 않았다.

13개 모의시험을 통과했다. 센서 0/1/10개 집계, 독립 고장 지연과 해제, HB 래치/Reset, 모드별 팬 대체운전, 댐퍼 지연, PICV 샘플 갱신/만료, 네 개 닫힘 확인, 위치/유량 모드 진단 구분, 비상/원격 우선권, F8 고장수 기준을 확인했다.

모의 엔진은 우선순위·타이머·관제점을 재현하되 실제 PI 수식은 검증하지 않는다. 실제 펌웨어·전기 배선·팬/밸브 응답은 시험하지 않았다. 테스트의 누수 입력은 가상으로 공급했으므로 전체 관제점 실장 완료를 의미하지 않는다.

실제 적용에 필요한 후속 자료와 작업은 [INTEGRATION.md](INTEGRATION.md)에 모았다. 코드 전체를 다시 설명하기보다 해당 항목을 먼저 해결하고 다음 리뷰에서 알람 상세를 이어간다.
