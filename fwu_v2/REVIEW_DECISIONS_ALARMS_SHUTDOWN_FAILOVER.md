# FWU v2 후속 코드 리뷰 합의서

작성: LJH / 2026-11-17
상태: 수정 방향 확정 문서. 아래 구현 상태 절은 합의 당시 기록이다. 후속 코드 반영 및 PC 모의시험은 완료했으며 현재 결과와 미완성 실장 항목은 DELIVERY_NOTES.md를 따른다.

## 기준과 적용 범위

- 원본 비교 기준: FWU-logic a017e7f1fe52ede6e510cee8c66d1125f07bd8b6의 FWU_v1 및 SMX01.
- 수정 기반: 이미 작성한 fwu_v2. Initialization, SF Control, PICV Control과 보조 블록의 기존 합의는 CONTROL_DECISIONS.md 및 IMPLEMENTATION.md를 따른다.
- 후속 대상: Alarm-1, Alarm-2, Alarm-3, Remote Shutdown, Failover. 관제점 명칭 정리는 해당 점을 사용하는 모든 v2 코드·XML·문서·시험에 함께 적용한다.
- 표준 제품을 위한 개발이며 QTS 납품용 적합성 선언이 아니다. 기존 두 코드의 공통 동작은 물리적 문제나 합의 충돌이 없다면 유지한다.
- SMX01 현장 전용 그룹·인접 장치 협조제어는 복원하지 않는다. 대체 운전 판단은 상위 제어기 역할이다.
- 이 문서의 후속 합의가 이전 문서의 상충 설명보다 우선한다.

## Alarm-1

1. 내부 SAT/RAT가 0 미만, SAH/RAH가 5 미만이면 해당 센서의 고온·저온 또는 고습·저습 알람 판정을 즉시 제외하고 기존 알람과 관련 상태를 정리한다. 센서 고장 알람의 기존 20초 초과 확인은 유지한다. 고장 확정 전에도 환경 한계 알람이 중복 발생하지 않게 한다.
2. 정상값으로 복구되면 기존 운전 조건에 따라 한계 알람 판정을 재개한다. 팬 운전 후 300초 확인 및 정지 시 한계 알람 해제는 유지한다. 룸의 상시 감시는 상위에서 담당한다. HMI는 진단 제외 상태를 정상 측정으로 표시하지 않는다.
3. 팬 개별 고장: 운전 명령 ON 및 속도 최소값 이상 조건을 60초 초과 확인한 뒤 기존 RPM 판정을 적용한다. 개별 고장마다 별도의 60초 지연을 추가하지 않는다.
4. 팬 종합 고장: 설치 팬의 절반 이상 고장 기준을 유지한다. 팬 수는 4/6/8 모델별 코드 상수이며 현재 초안은 8대다. 신규 팬 정압·풍량 곡선과 잔여 팬 보상 가능 범위에 따라 고장 허용 대수를 팬 개발팀에서 확정해야 한다는 주석을 남긴다.
5. FMS 고장 추정은 기존 RPM·차압 조건과 20초 확인을 유지한다. 실제 저풍량과 센서·배선 이상을 구별하지 못한다는 짧은 주석을 남긴다. 이 알람만으로 정지 또는 제어 모드 변경을 추가하지 않는다.
6. 통신 정상 시 운전 판정은 RPM >= 기준, 고장 판정은 RPM < 기준으로 경계를 일치시킨다. Initialization의 8개 비교식에는 이미 로컬 반영했다.
7. 단일 PICV 진단을 복원하지 않는다. 네 밸브 진단은 PICV Feedback에서 담당한다.

## Alarm-2

- 누수 입력 ON이 5초를 초과하면 알람, OFF이면 타이머와 알람 해제. 누수만으로 정지하지 않는다.
- 필터 입력 ON이 30초를 초과하면 알람, OFF이면 타이머와 알람 해제.
- 두 시간은 별도의 이름 있는 상수로 선언한다. 새로운 설정 VP로 만들지 않는다.
- 필터 수명 예측 특허 v8 방식은 이번에 구현하지 않는다. 향후 전환풍량·기준풍량·운전 이력 등을 이용한 예측으로 확장할 수 있다는 주석을 유지한다. 기존 알람과 진단용 차압 설정의 충돌, 실제 전환 순간 기록, FMS 정확도 및 이력 저장 확인이 필요하다.
- 외부 센서 고장 판정은 Zone CZT/HZT/RDP Alarm에 있으므로 Alarm-2에 중복 구현하지 않는다.
- 누수 DI 등록과 실제 배선 연결은 실장 작업이다. 기존 누수 판정 로직 자체를 누락된 것으로 취급하지 않는다.

## Alarm-3

- 팬 통신 판정 READPOINT_ALARM == 8 및 10초 초과 확인을 유지한다. 해당 DDC 지원은 사용자 확인 사항이며 불필요하게 재논의하지 않는다.
- 통신 정상 복구 시 알람 해제와 기존 팬 AO/통신 출력 복귀 방식을 유지한다.
- ATS는 블록 다이어그램의 CH2 RS485 구성으로 연결하며 기존 통신 감시를 유지한다. code_request.md의 ATS DI 요구와 다른 점을 실장 확인 사항으로 기록한다. SuperCap DI와 혼동하지 않는다.
- 10초 지연은 이름 있는 상수로 선언한다.
- 기존 단일 유량계 감시는 복원하지 않는다. 새 PICV Feedback의 네 입력 집계와 연결한다.
- 기존 주요 블록 순서 Initialization → PICV → SF → Alarm-1 → Alarm-2 → Alarm-3 → Remote Shutdown → Failover는 유지한다. Alarm-3을 반드시 Initialization보다 먼저 실행해야 한다는 기존 주석은 정리한다.

## Remote Shutdown

- 화재 입력 확인은 기존 3초 초과, 입력 해제 시 화재 알람 해제를 유지한다. 시간은 상수화한다.
- VP_FWU_Smoke Action은 VP_FWU_Smoke_Action_Set으로 변경한다. HMI 표시는 ‘화재 감지 시 운전 방식’. 0=알람만/운전 유지, 1=정지이며 기본값 0을 유지한다.
- 로컬·리모트 및 수동·자동 여부와 무관하게 Remote Shutdown 명령 또는 화재 알람+정지 설정이면 기존 정지 처리를 적용한다.
- 일반 BMS 운전 ON/OFF와 강제 Remote Shutdown 명령을 구분한다.
- P2 출력 강제, P11 OFF 기록, 팬 정지 후 댐퍼 닫힘을 유지한다. 해제 시 P2를 풀며 별도 재기동 승인·리셋을 추가하지 않는다.
- 더 높은 우선순위에 운전 명령이 남아 있으면 해제 후 재기동할 수 있음을 주석에 정확히 적는다. ‘반드시 작업자가 재기동해야 한다’고 보장하는 설명은 삭제한다.
- 소프트웨어 운전 유지 설정은 하드웨어 화재 차단 회로를 무효화하지 않는다. 실제 배선의 작동은 현장에서 확인한다.

## Failover

- 발생 원인은 v1의 세 가지 유지: SAD Not Open Alarm, SAD Full Close Alarm, SF Failure Alarm.
- SMX01 그룹 제어 중 Command OFF 조건은 제거 상태를 유지한다.
- 새 댐퍼 신호 모순·위치 불명, PICV 개별 이상은 개별 알람만 유지하고 Failover 원인으로 추가하지 않는다.
- 위 원인 중 하나라도 있는 상태가 5초를 초과하고 Failover 알람이 0이면 알람을 설정하고 Command/Command-HMI에 P11 OFF를 한 번 기록한다.
- 지속적인 정지 강제나 재기동 금지를 추가하지 않는다. 상위 우선순위 운전 명령이 있으면 P11 OFF가 유효 명령이 되지 않을 수 있다.
- 원인이 사라져도 Failover 알람은 유지한다. 원인이 없는 상태에서 Reset이 들어와야 해제한다.
- Reset 입력은 5초 초과 후 기존 P11 쓰기로 0으로 복귀한다. 알람 해제 자체의 5초 지연이 아니다.
- 원인 확인 시간과 Reset 복귀 시간은 값이 같아도 별도 상수로 선언한다.

## 기존 v2 및 파생 블록과의 연결

- Initialization: 외부 센서 종류별 최대 10개, 명시한 사용 개수만 반영, 기존 유효성 기준, 상위 대표값 수신 대안 주석을 유지한다. HB 사용 설정·기본 30초 시간 설정·기존 복구 정책은 기존 합의를 따른다.
- SF Control: 외부/해당 내부 센서 고장 대체운전, HB 마지막/최대 출력, 최소 30%, Delta T 방향과 -2 임시값, HMI 수동입력 제한 주석 등 기존 합의를 보존한다.
- PICV Control: 네 밸브 공통 AO3 명령, CH3 RS485 피드백, SAT 고장 시 100% 명령 및 기존 정지/수동/우선순위 정책을 보존한다. 실제 위치·유량 제어 모드에 따른 명령 의미는 실장 확인 사항이다.
- PICV Feedback: 기존 Alarm의 개도 편차·유량 감시를 네 밸브로 확장한 보조 블록이다. 수신 유효성, 0~100% 개도 범위, 위치 모드 편차, 선택적 유량 검사 및 네 밸브 모두 유효한 개도 5% 미만인지 집계한다. 실제 CH3 수신 어댑터는 미완성이다. 미연결/오래된 0을 닫힘으로 인정하지 않는다.
- PICV Feedback의 Input Enable/OK/Sample Seq/Timeout, 진단 모드 및 유량 감시 enable은 구현 과정에서 구체화된 인터페이스이며 장비에서 지원·연결 완료됐다는 의미가 아니다. 수신 10초는 폴링 주기에 따라 확인할 임시값이다.
- Damper Signal Alarm: 0/0 위치 불명 120초, 1/1 모순 5초 및 기존 설정·확인 주석 유지. 기존 댐퍼 보호 조건과 별도로 개별 알람만 발생한다.
- Zone CZT/HZT/RDP Alarm: 각 독립 블록에서 최대 10개 센서 고장 확인. 기존 온도/차압 판정 정책을 유지한다.
- LDPL §6.2 p72: ‘하나의 로직에서는 10개까지(0~9)의 타이머’를 제공한다. 별도 등록된 로직 간 번호 중복은 가능하다. 같은 로직에서 서로 다른 용도에 같은 번호를 쓰지 않는다. 읽기와 reset에는 같은 번호를 사용한다. 파일을 합칠 때 타이머를 그대로 중복시키면 안 된다.

## 코드 작성 및 명칭 규칙

code_request.md의 원문을 확인했다. 아래는 원문 규칙을 충돌 없이 적용하는 기준이다.

- 일반 코드 변수: 소문자 snake_case. 예: sf_fail_count.
- Boolean: b_ 접두어와 snake_case. 예: b_fail_total. 원문 bFan_ON 예시는 snake_case와 일관되지 않아 기존 v2의 b_ 방식으로 통일한다.
- 상수: 대문자와 밑줄. 예: FAILOVER_CONFIRM_SECONDS. Timer/LOOP2 ID도 의미 있는 대문자 상수로 선언한다.
- VP 이름: VP_ 접두어를 유지한다.
- 수정 블록에 LJH와 실제 수정 날짜, 기술 설명의 S/E 표기를 적용한다. JSY 등 기존 원저자 이력은 지우거나 모두 LJH로 바꾸지 않는다.
- 주석은 코드 동작, 확인이 필요한 팬/밸브 제원, HMI 입력 제한, 현장 연결, QTS와의 차이 등 개발에 필요한 내용만 적는다. 승인 대화나 리더 성향 같은 내용은 넣지 않는다.

### 변수명과 관제점 이름의 구분 및 정리 계획

Python 변수명에는 원래 공백을 넣을 수 없다. READPOINT("VP_FWU_Smoke Action") 안의 문자열은 Python 변수가 아니라 DDC 관제점 이름이다. 리더 문서가 모든 기존 관제점의 소문자 변환까지 명시한 것은 아니다.

이번 후속 수정에서 v2 관제점의 공백은 밑줄로 정리한다. VP_ 및 FWU/SF/PICV 등 기존 식별 약어의 대소문자는 유지한다. 하이픈·점 등 나머지 문자는 장치 점 식별 규칙과 연관되므로 무조건 치환하지 않는다. Smoke Action은 승인한 VP_FWU_Smoke_Action_Set을 사용한다.

1. 수정 전 구명칭→신명칭 대응표를 만든다. 이미 같은 밑줄 이름이 있으면 충돌을 해결한다.
2. v2 Python의 읽기/쓰기/우선순위/LOOP 참조, 관제점 XML 정의, 이름 참조를 쓰는 외부맵, 시험·문서를 함께 변경한다. 원본 SMX01/v1은 변경하지 않는다.
3. 하드웨어 주소·관제점 ID·통신 레지스터는 명칭 정리만을 이유로 바꾸지 않는다.
4. 외부 HMI/BMS 프로젝트는 현재 작업 파일 밖에 있으므로 실제 수정 완료로 표시하지 않는다. 대응표를 전달해 함께 갱신하도록 한다.
5. 파일명과 DDC 로직 표시명은 Python 변수명이 아니다. 이번 명칭 정리만을 위해 파일명을 일괄 변경할 필요는 없다.

## 구현 상태와 다음 검증

이미 로컬 반영: 필터 향후 예측 주석, 신규 팬 특성 확인 주석, FMS 진단 한계 주석, Initialization RPM >= 경계 수정.

아직 후속 구현 필요: 내부 센서 무효 시 한계 알람 억제, 시간 상수화, Smoke 설정점 및 공백 명칭 정리, 관련 주석·문서·시험 동기화. 이번 문서 작성으로 실행 코드가 바뀐 것은 아니다. 기존 ZIP과 원격 저장소도 갱신되지 않았다.

후속 확인:
- Python 구문, XML 파싱, 이름/ID 충돌·미정의 참조·구명칭 잔존 검사.
- 블록별 타이머 0~9 범위와 다른 용도 중복, 기존 실행 순서 및 보조 블록 등록 확인.
- 센서 무효/고장 지연/복구와 한계 알람 중복 방지, 기존 유효 센서의 한계 알람 유지 시험.
- 누수/필터, 통신 이상/복구, 화재 설정 0/1, P1/P2/P5/P11 출력과 해제 후 명령 잔존, Failover 1회 OFF·래치·리셋 시험.
- 기존 v2 시험을 새 관제점명과 맞추고 PICV 네 입력·일반 정지 대기·강제 정지 연계를 확인한다.
- PC/DDC 후속: 실제 펌웨어·HMI·통신맵, CH1 팬/CH2 ATS/CH3 PICV, AO3 2~10V 및 배선, 미연결 누수점, 신규 팬 성능과 안전 회로 시험. 소프트웨어 모의시험만으로 이를 완료 처리하지 않는다.
