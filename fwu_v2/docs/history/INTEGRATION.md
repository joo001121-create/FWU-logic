# 실장 전 연결 조건

## 1. 현재 제공 범위

이번 결과물은 실행 분기와 관제점 정의를 갖춘 **F8 제어 로직 초안**이다. 제조사 레지스터 주소와 신형 IO 모듈 설정을 확정하지 못했으므로 다음 항목이 완료되기 전에는 실장 완료로 판단하지 않는다.

| 항목 | 현재 상태 | 필요한 작업 |
|---|---|---|
| PICV AO3 | AO3 제어점 명칭의 공백 정리, 출력 로직 유지 | 새 Combined IO의 실제 주소, 2~10 V 설정과 % 환산, 병렬 입력 부하 확인. 기존 XML은 0~10 V이며 그대로 실장하지 말 것 |
| PICV CH3 | 일반 DDC 관제점 읽기로 수정, 실제 12점 미등록 | Belimo Modbus 주소·레지스터·자료형·배율 및 통신 경보 설정을 등록 |
| 팬 CH1 | 기존 팬 CH1/CH2 주소·포트 유지, 명칭만 정리 | HW 확인에 맞춰 팬 8대의 CH1 주소·포트 배치와 충돌 검증 |
| ATS | 기존 통신점과 알람 유지 | 블록 다이어그램 기준 CH2 RS485로 연결. 리더 문서의 DI 표기 차이는 확인 사항이며 SuperCap DI와 별도 관리 |
| 누수 입력 | 기존 `FWU_LEAK_DETECT` 미정의 상태가 남음 | 실제 DI 주소 확인 후 정의. 시험에서는 이 입력과 PICV 실제 통신점 12개를 모사 |
| 외부 상위 통신 | HB·센서 처리와 설정점 추가 | HMI/BMS 읽기·쓰기 맵 연결. 기존 외부맵은 자동 확장하지 않았음 |
| DDC | 보조 로직 5개 등록 | 엔진의 블록 수·ID·실행 순서, 타이머 분리 확인 |

기존 단일 `FWU_PICV_FEEDBACK`, `FWU-Flow.Rate`는 v2 제어·알람에서 더 이상 읽지 않는다. 기존 물리·외부맵에는 남아 있으므로 새 맵 작성 시 폐기/미사용 처리하고 HMI에서 유효한 신형 계측값처럼 표시하지 않는다.

## 2. PICV 실제 통신점 연결 — LDPL 재검토 수정안

별도 수신 어댑터는 만들지 않는다. DDC 엔지니어링 도구에서 CH3의 밸브별 Modbus 관제점을 등록하고, PICV Feedback이 기존 READPOINT_ALARM/READPOINT로 읽는다. 다음 이름의 점은 VP가 아니라 실제 통신점이어야 한다. n은 1~4다.

| 실제 통신점 | 단위·내용 | 기존 표시용 VP |
|---|---|---|
| `FWU_PICV-n.Position` | 실제 개도, % | `VP_FWU_PICV-n_Position` |
| `FWU_PICV-n.Flow` | 유량, L/min | `VP_FWU_PICV-n_Flow` |
| `FWU_PICV-n.Temperature` | 냉수 출구 온도, ℃ | `VP_FWU_PICV-n_Temperature` |

총 12개다. 실제 주소·레지스터·자료형·배율은 `PICV_POINT_MAPPING.csv`에 TBD로 남겼다. 해당 표는 등록 목록이며, 통신 설정이 완료된 XML이 아니다. 주소를 임의로 만들지 않았다. 코드의 이름과 실제 등록 이름을 일치시킨다.

`VP_FWU_PICV_Input_Enable=0`에서는 실제 PICV 통신점을 읽지 않고 Feedback_Valid와 All_Closed를 0으로 둔다. 입력 이상 알람은 기존처럼 표시한다. 12개 점을 등록하고 통신·단위·알람을 확인한 뒤 엔지니어가 Enable을 1로 설정한다. HMI에서는 서비스 설정으로 제공할 수 있다.

Enable=1이면 밸브별 세 통신점의 알람 값이 모두 0일 때만 읽은 값을 기존 VP에 기록한다. 개도가 0~100%를 벗어나면 유효하지 않게 처리한다. 통신점에 경보가 있으면 기존 표시값을 남기되 Feedback_Valid=0으로 표시한다. HMI는 그 값을 현재 정상 측정값으로 표시하지 않는다. 표시용 VP는 읽기 전용으로 제공한다.

Input_OK/Sample_Seq/Sample_Prev와 Input_Timeout은 더 이상 코드에서 사용하지 않는다. 기존 XML 정의만 보존했다. HMI에서 수정하거나 별도 코드로 값을 만들 필요가 없다. 이전의 Seq 갱신 10초 판정도 없으며, 통신 이상 검출은 DDC 통신 경보 설정에 따른다. 실제 검출 시간을 시험해 정한다.

DDC 알람 0은 독립적인 새 샘플 수신 증명이 아니다. **첫 응답 전에도 알람 0과 개도 0을 반환하면 닫힘으로 오인할 수 있으므로 재시작 시험이 필요하다.** Enable=1이 유지된 재부팅도 시험한다. LDPL만으로 이 부분이 보장된다고 표시하지 않는다. 상세 내용과 보류 판단은 `LDPL_REVIEW.md` 4절에 기록했다.

Comm_Fault는 기존처럼 입력 사용 불가를 뜻한다. 단선·전원 상실을 구별하는 제조사 진단은 구현하지 않았다. 세 입력 중 하나의 경보만 있어도 해당 밸브 전체 입력이 무효해져 정상 정지가 대기할 수 있다.

## 3. PICV 제어 모드와 알람

| 설정 | 값 | 적용 |
|---|---|---|
| `VP_FWU_PICV_Control_Mode` | 0 기본 | 적용 모드 미확정. 명령-개도 편차 검사 안 함 |
| 위 설정 | 1 | 위치 제어. 기존 ±30% 범위 밖 40초 초과 편차 검사 |
| 위 설정 | 2 | 유량 제어. 명령율과 개도율 비교 안 함 |
| `VP_FWU_PICV_Flow_Check_Enable` | 0 기본 | 밸브별 유량 기준 미확정. 저유량/패싱 검사 보류 |
| 위 설정 | 1 | 기존 열림 30%·저유량 30 L/min, 닫힘 1%·통과유량 10 L/min 기준 사용. 실제 설계 유량에 맞게 설정값 확인 필수 |

위 모드 VP는 **진단 로직이 어떤 비교를 할지 지정하는 값**이다. 이 VP를 바꾼다고 실제 Belimo의 운전 모드가 바뀌지 않는다. Belimo 설정과 일치시켜야 한다. 유량 모드용 목표-실측 유량 편차 알람은 V'max·유량특성·허용편차 확인 후 별도 결정한다.

`Monitor Ready`는 네 입력이 유효하고 진단 설정이 지정됐음을 나타내는 최소 상태점이다. 전체 고장 진단의 완전성을 보장하지 않는다. 특히 유량 모드의 명령 추종 진단은 미구현이다. HMI에서는 알람 0만 보고 ‘진단 정상’이라고 표시하지 않는다.

실제 개도 4개가 모두 유효하고 각각 5% 미만일 때만 `All Closed=1`이다. 일부 수신 실패 또는 미폐쇄에서는 정상 정지가 계속 대기한다. 비상 P1 및 원격 P2의 출력 강제는 이 대기를 따르지 않는다.

## 4. 상위·외부 센서와 HMI

- `Upper Comm Enable` 기본 0, 종류별 Count 기본 0. 실장 초기 설정에서 상위가 있으면 감시를 켜고 실제 센서 수와 통신맵을 맞춘다.
- Enable=0이면 통신 알람을 해제하고 HB 이전값·타이머를 동기화한다. 다시 켤 때 30초 기본 유예를 새로 시작한다. 감시 중 알람은 HB 복구만으로 해제하지 않고 Reset이 필요하다.
- 외부 CZT/HZT/RDP는 감시 미사용 때 PV Valid=0이다. CZH는 합의대로 기존 유효성 정책을 유지하며 Count만 적용한다.
- Count는 0~10 정수, 상위 HB Timeout은 양수, 댐퍼 지연은 0 이상으로 입력하도록 UI를 제한한다. XML min/max만으로 실제 UI 입력 제한이 보장된다고 가정하지 않는다.
- 팬 모드는 정수 0~4, 수동 속도는 정지 0 또는 설정 최소~최대 범위. 최소가 최대를 넘는 설정을 막는다. 수동 출력의 새 코드 클램프는 추가하지 않았다.
- `SF Count` VP는 이전 인터페이스 보존용이다. F8 고장 집계는 코드 상수 8을 사용하며 이 VP만 변경해서 F4/F6로 바뀌지 않는다.
- 새 관제점 ID와 주소는 저장소 내 중복을 피한 초안 할당이다. DDC 도구에서 지원 범위, 생성/가져오기, 실제 backup/default 동작을 확인한다. 제조사 통신 주소와는 다르다.

## 5. 회사 PC 시험

1. PICV 실제 통신점 12개·신형 물리 맵·누수 DI 연결 및 외부 공개점을 완성한다.
2. 기존 펌웨어 지원 확인을 전제로 한 `READPOINT_ALARM`, `WRITEPOINT_PRI` 등 호출을 엔지니어링 도구에서 컴파일·실행한다. API 이름을 임의로 바꾸지 않는다.
3. 동일 출력점에 모드별 LOOP2 ID를 쓰는 v1 방식을 유지했으므로, 엔진에서의 상태 분리·초기화를 확인한다.
4. 전원 재투입·DDC 이중화 절체에서 전달점의 초기화와 유효성, 우선순위 잔존값, 타이머 동작을 확인한다.
5. 정상/고장/복구, 미폐쇄 대기, 비상·원격 강제, 팬 AO 전환을 실제 신호와 함께 시험한다.
6. SAT PI·팬 PI 응답, ΔT -2 임시값, 팬 최소 30%, 새 팬 환산값을 팬/HW 개발팀과 검증한다.

## 6. 이번 관제점 명칭 변경

POINT_RENAME_MAP.csv의 466개 이름을 기준으로 v2 코드와 XML을 함께 갱신했다. Smoke 설정은 VP_FWU_Smoke_Action_Set이며 HMI 표시는 ‘화재 감지 시 운전 방식’이다. 기본 0=알람만, 1=정지를 유지한다. ID와 물리 주소는 그대로다. 외부 HMI/BMS의 이름 참조와 표시명은 현장 프로젝트에서 갱신해야 한다.

SAT/RAT < 0, SAH/RAH < 5인 동안 해당 한계 알람은 해제되며 센서 고장 확정은 기존 20초 초과 조건을 따른다. HMI는 한계 알람이 0이라는 이유만으로 정상 측정으로 표시하지 않는다. 이 판정을 위한 신규 VP는 추가하지 않았다.
