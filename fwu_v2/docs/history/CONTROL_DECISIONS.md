### 1.1 제품의 목적

- 목표는 표준 FWU 라인업의 제어 로직이다. QTS 수주 프로젝트나 QTS 납품용 코드가 아니다.
- QTS RFP와 SMX01 현장은 회사가 확보한 고객 요구의 참고 사례다. 표준품에 필요한 사항을 채택하되 모든 요구를 일괄 적용하지 않는다.
- SMX01은 인도네시아 시나르마스에 납품한 이전 FWU이며, 폴더는 2026-11-02 현장 업데이트 기준이다.

- 이후의 명시적 합의가 이전 논의보다 우선한다. 예: 댐퍼는 항상 있는 것으로 구현, 외부 센서는 종류별 최대 10개, PICV 명령은 AO3 공통 출력.

## 3. Initialization

이 블록은 기동 때 한 번만 실행되는 초기 설정 파일이 아니다. 반복해서 공통 상태·센서 집계·명령 출처 등을 계산한다.

### 3.1 상위 제어기 통신

| ID | 상태 | 결정 |
|---|---|---|
| I-01 | 변경 확정 | BMS PLC 전용 협조제어는 제외하되 상위 통신의 정상 여부를 확인하는 Heartbeat 감시는 유지한다. DCCM 등 다른 상위에도 사용할 수 있게 통신점과 공급 규칙을 현장에서 연결한다. |
| I-02 | 변경 확정 | 상위 통신 감시 사용/미사용 설정 VP를 둔다. 상위 제어기가 없는 구성은 감시를 끄고 외부 정보가 필요 없는 로컬 모드로 운전한다. |
| I-03 | 변경 확정 | Heartbeat 타임아웃을 설정 VP로 만들고 기본값은 30초로 둔다. 현장 합의에 따라 변경할 수 있게 한다. 송신 주기와 타임아웃은 서로 다른 값이다. |
| I-04 | 유지 확정 | Heartbeat 값의 변화로 통신을 감시한다. 알람 래치와 정상 통신 확인 후 Reset으로 해제하는 기존 방식을 유지한다. 통신이 재개됐다는 이유만으로 즉시 자동 복귀시키는 정책으로 바꾸지 않는다. |
| I-05 | 유지 확정 | 통신 이상 시 팬 속도 대응은 v1의 QTS 참고 정책을 유지한다. 세부 범위는 S-03을 따른다. |

상위가 Heartbeat를 어떤 값과 주기로 갱신할지, DDC 통신맵의 어느 점에 쓸지는 현장 인터페이스 업무다. 표준 로직에서 감시 기능 자체를 삭제하지 않는다. 기존 검토에서 Heartbeat 외부 맵 누락이 확인됐으므로 VP를 선언하는 것만으로 연동 완료라고 판단하지 않는다.

감시 사용 VP의 이름·기본값, 감시를 끄거나 다시 켰을 때의 기존 알람·Prev·타이머 정리는 구현 전에 명시해야 한다. 감시 미사용이 오래된 외부 센서값을 정상값으로 만드는 우회 조건이 되어서는 안 된다. 상세 전환 절차가 이미 합의된 것으로 처리하지 않는다.

### 3.2 외부 센서 집계

| ID | 상태 | 결정 |
|---|---|---|
| I-06 | 변경 확정 | 냉복도 온도(CZT), 열복도 온도(HZT), 룸 차압(RDP), 냉복도 습도(CZH)를 각각 최대 10개 수신 VP로 구성한다. |
| I-07 | 변경 확정 | 종류별 사용 개수를 설정하고 해당 범위만 집계한다. 값이 0인지, 이전과 달라졌는지로 ‘연결된 개수’를 자동 추정하지 않는다. 사용 대상으로 설정한 점이 실제 맵에 연결됐는지는 시운전에서 확인한다. |
| I-08 | 유지 확정 | 평균·최대·최소 선택 및 센서 유효성 판단은 기존 방식을 유지한다. CZT/HZT는 평균 또는 최대, RDP는 평균 또는 최소를 사용한다. CZH 집계도 기존 정책을 출발점으로 한다. |
| I-09 | 주석 | 상위에서 계산한 대표값 하나를 전달받는 구성도 가능하다. 이 경우 해당 종류를 1개 사용하도록 구성할 수 있다. 별도의 대표값 전용 제어 모드를 이번에 추가하지 않는다. |

‘실제 연결 개수만 반영’은 설정한 사용 개수와 실제 통신맵을 일치시킨다는 뜻이다. 예를 들어 10점 중 6점을 사용하면 나머지 4점은 집계·센서 알람 대상에서 제외한다. 사용 개수 0일 때 나눗셈을 하지 않으며, 외부 값이 없는 모드를 정상 PI 입력으로 사용하지 않는다. 구체적인 초기 사용 개수는 모델·현장 설정표에서 지정한다.

센서 유효성 유지의 범위:

- CZT/HZT: 기존 온도 하한 판정과 20초 초과 고장 확인을 유지하고, 고장 확정된 센서를 집계에서 제외한다.
- RDP: 기존 0 이하 판정과 20초 초과 확인을 유지한다.
- CZT/HZT/RDP는 기존 상위 통신 상태 및 PV Valid와 연결한다. 유효한 센서가 없으면 기존의 PV/Valid 처리와 대체운전으로 연결한다.
- CZH는 기존에 별도 고장 제외·통신 유효성 필터가 없었다. 이번 합의로 새 진단 기준을 추가하지 않는다.
- 상위가 정상 범위 안의 오래된 값을 계속 보내는 경우까지 센서 고장을 판별할 수 있다는 뜻은 아니다. 새로운 상한·고착·개별 freshness 진단은 승인하지 않았다.

## 4. SF Control

### 4.1 모드와 고장 대응

| ID | 상태 | 결정 |
|---|---|---|
| S-01 | 유지 확정 | 모드 0 고정속도, 1 RAT, 2 RDP, 3 RAT−SAT, 4 CZT의 다섯 가지 구성을 유지한다. SAT 단독 팬 모드는 추가하지 않는다. |
| S-02 | 변경 확정 | RAT 모드에서 RAT 고장, ΔT 모드에서 RAT 또는 SAT 고장이 확정되면 해당 PI 대신 기존 고정속도 SP로 운전한다. 현재 모드가 사용하지 않는 내부 온도센서 고장만으로 모드를 바꾸지 않는다. |
| S-03 | 유지 확정 | BMS 통신 알람 시 v1의 유지/최대 선택을 유지한다. 모드 0은 기존 속도 유지, 모드 1은 `SF Speed Max` 사용. 적용 대상은 RDP/CZT 및 Remote 고정속도이며, Local 고정속도/RAT/ΔT는 기존 모드를 유지한다. |
| S-04 | 유지 확정 | BMS는 정상이나 RDP/CZT의 유효 센서가 없는 경우 기존 고정속도 SP 대체를 유지한다. 상위가 없는 구성은 Local 고정속도·RAT·ΔT 등 독립 운전 가능한 방식으로 설정한다. |
| S-05 | 유지 확정 | ΔT는 RAT−SAT로 계산하고 v1의 PI 방향(type 1)을 유지한다. 기본 목표는 기존 SMX01의 −2를 일단 유지한다. |
| S-06 | 주석 | −2℃는 일반적인 냉방 운전의 양의 RAT−SAT와 맞지 않아 출력이 상한에 머무를 수 있다. 기존값을 임시로 유지한 것이며 목표값·센서 정의·운전 조건을 확인해 조정해야 한다. |
| S-07 | 유지 확정 | 팬 최소 속도는 30%를 유지한다. QTS의 20% 이하 하한 요구와의 차이는 주석에 남긴다. 20% 적용 전 팬 개발팀에 안정 운전 가능 여부를 확인한다. |

S-03의 ‘유지’는 v1에서 현재 속도점에 새 값을 쓰지 않는 방식이다. 별도 영구 저장한 고장 직전 RPM을 복원하는 기능이 아니다. v1에 있는 유지값이 최소 속도보다 작을 때 최대값으로 대체하는 예외도 함께 검토·유지한다. 예를 들어 최대 속도 설정이 95%이면 최대 선택의 목표는 95%다. 모든 통신 고장에서 무조건 100%로 운전한다는 의미가 아니다.

### 4.2 댐퍼와 정지 순서

| ID | 상태 | 결정 |
|---|---|---|
| S-08 | 유지 확정 | 자동 기동은 댐퍼 OPEN 명령 후 전개방 확인을 기본으로 한다. 전폐이면 팬 속도 0, 전개방·전폐 모두 아니면 기존 속도를 유지하는 구조를 유지한다. |
| S-09 | 유지 확정 | 기존 일부 닫힘, 전폐, 미개방, 미폐쇄 알람과 연결된 보호 동작을 유지한다. 일부 닫힘 알람을 새로 전체 정지 조건으로 올리지 않는다. |
| S-10 | 변경 확정 | 네 댐퍼 각각에 위치 미확인(OPEN=0, CLOSE=0)과 신호 모순(OPEN=1, CLOSE=1) 알람을 추가한다. 위치 미확인은 운전 중·OPEN 명령 조건에서 120초, 신호 모순은 5초 지속을 기준으로 한다. 각각 공통 지연 설정 VP를 두는 방향이다. |
| S-11 | 변경 확정 | S-10의 추가 알람 자체로 팬 정지나 Failover를 새로 걸지 않는다. 정상 신호로 돌아오면 해당 알람을 해제한다. 기존 전폐·미개방 보호가 동시에 성립하면 그 보호는 계속 적용된다. |
| S-12 | 주석 | 신호 모순 5초는 순간적인 접점 변화로 알람이 발생하는 것을 줄이기 위한 임시 지연값이다. 실제 액추에이터 접점과 시운전 결과에 따라 조정할 수 있음을 남긴다. |
| S-13 | 변경 확정 | 정상 자동 정지는 PICV 닫힘 명령 후 네 밸브 모두의 유효한 실제 개도율이 5% 미만인 것을 확인한 뒤 팬을 정지하고, 팬 정지 확인 후 댐퍼를 닫는다. 평균 개도나 명령값으로 완료 판정하지 않는다. |
| S-14 | 유지·주석 | 정상 정지 중 밸브 닫힘을 확인하지 못하면 기존처럼 기다리는 방향을 유지한다. 피드백 고장·미폐쇄를 알리고, 정지 대기 제한시간이나 대체 정지 정책이 추가로 필요할 수 있음을 주석에 남긴다. 임의의 강제정지 시간을 추가하지 않는다. 비상/원격 정지에 이 대기를 적용하지 않는다. |

댐퍼 0/0은 이동 중일 수도 있고 신호 이상일 수도 있다. 1/1은 모순된 접점 상태이며 물리 위치를 확정하지 않는다. 추가 알람은 상태를 드러내기 위한 것이지 실제 댐퍼 위치를 복원하는 기능이 아니다.

### 4.3 출력과 입력 범위

| ID | 상태 | 결정 |
|---|---|---|
| S-15 | 유지·주석 | 팬 하나라도 통신 이상이면 기존처럼 전체 팬의 AO 출력 경로로 전환한다. 같은 제조사 팬에서 지원하는 것으로 설계하되, 실제 팬의 Modbus/AO 전환·우선권·Run 신호·RPM/전압 환산·복구 동작을 확인하라는 주석을 남긴다. |
| S-16 | 유지 확정 | 일반 출력 갱신 주기와 기존 PI 초기화·출력 우선순위 구조를 출발점으로 유지한다. 이번 합의로 새로운 출력 주기나 PI 시작값을 만들지 않는다. |
| S-17 | 유지·주석 | 모드 선택은 HMI/BMS UI가 정수 0~4만 보내는 것을 전제로 한다. 코드에 새 잘못된 모드 처리 분기를 추가하지 않는다. 직접 입력 경로가 생기면 값 검증이 필요하다는 주석을 남긴다. |
| S-18 | 유지·주석 | 수동 속도 입력의 범위 방어를 이번에 별도 추가하지 않는다. HMI에서 정지값 0과 허용 운전 범위를 구분하고, 운전 속도는 설정 최소~최대 이내만 입력하도록 안내한다. 직접 쓰기 경로에도 같은 조건이 필요하다. |
| S-19 | 유지·주석 | 최소·최대 설정의 역전 등은 UI/설정 단계에서 막는 기존 합의 방향을 따른다. 코드가 모든 비정상 설정을 보정한다고 설명하지 않는다. |

고정속도 SP와 Speed Value는 현재 로직에서 백분율을 바탕으로 RPM/AO로 환산된다. 대화의 ‘고정 RPM’ 표현을 이유로 SP 단위를 RPM으로 바꾸지 않는다.

## 5. PICV Control

### 5.1 하드웨어와 네 밸브 구성

| ID | 상태 | 결정 |
|---|---|---|
| P-01 | 변경 확정 | PICV/UFM은 4대다. SAT PI는 공통으로 계산하고 AO3 하나의 아날로그 명령을 네 밸브에 전달한다. 네 개의 독립 SAT PI를 만들지 않는다. |
| P-02 | 변경 확정 | 실제 개도율, 유량, 장치 위치의 물 온도는 밸브별로 CH3 RS485를 통해 읽는다. Combined IO #2에 그려진 기존 UI 4개 아날로그 개도 입력은 사용하지 않는다. |
| P-03 | 변경 확정 | 밸브별 고장과 통신 상태를 구분해 감시한다. 한 밸브의 고장만으로 정상 밸브와 팬을 일괄 정지시키지 않는 방향이다. 정상 정지의 전체 닫힘 조건은 S-13을 따른다. |
| P-04 | 구현 전 확인 | 수신 값은 개도·유량·온도 각 4개로 총 12개가 필요하다. 통신 입력을 모두 VP라고 부르지 않는다. 실제 Modbus 점, 필요한 가공 VP, 알람점을 분리하고 기존점 재사용 여부를 확인해 수량을 확정한다. |

팬 8대를 CH1에 연결하고 UFM 4대를 CH3에 연결한다는 HW 설명은 반영하되, 기존 v1의 팬 CH1/CH2 및 CH3 ATS/유량계 맵을 그대로 새 배선이라고 취급하지 않는다. 실제 주소·통신 설정·포트별 장치 구성을 확인한 뒤 설정 파일을 수정해야 한다. 폴링에 따른 시차는 있으며 네 장치가 같은 순간에 측정·응답한다고 가정하지 않는다.

### 5.2 운전 동작

| ID | 상태 | 결정 |
|---|---|---|
| P-05 | 유지 확정 | 자동 운전 중 Command=1, SF Status=1일 때 SAT PI로 냉방을 조절한다. SAT 고장이 확정되면 100% 냉방 요구를 출력하는 기존 방향을 유지한다. |
| P-06 | 정정·확인 | Belimo 유량 제어 모드의 100%는 설정 최대 유량 요구이며 물리적 완전 개방을 보장하지 않는다. ‘SAT 고장 시 100% 개방’이라는 이전 표현을 ‘100% 냉방 요구’로 정리한다. 실제 적용 모드와 V'max는 HW 담당자 확인 후 확정한다. |
| P-07 | 유지 확정 | Command=1인데 SF Status=0이면 새 PI 출력 없이 기존 명령을 유지하는 동작을 유지한다. 팬 정지만으로 새 PICV 닫힘 분기를 추가하지 않는다. |
| P-08 | 유지 확정 | 자동 일반 정지 Command=0의 닫힘 명령, 수동에서 자동 P5 해제, 비상 P1 및 원격 정지 P2의 기존 출력 강제를 유지한다. P-07을 비상 정지 시 밸브 유지로 해석하지 않는다. |
| P-09 | 유지·주석 | SAT 고장 시 PI 내부 상태를 별도로 초기화하지 않는 기존 방식을 유지한다. 복구 직후 출력·급기온도 변동을 시험하라는 주석을 남긴다. P11은 PI 적분 상태나 고장 직전 값을 별도로 보관하는 저장소가 아니다. |
| P-10 | 유지·주석 | 수동에서는 일반 Command=0만으로 PICV를 자동 닫는 기능을 추가하지 않는다. 팬 정지 중 냉수 공급이 계속되면 과냉·결로 등이 생길 수 있어 HMI 경고나 운전 안내가 필요할 수 있음을 남긴다. |
| P-11 | 보류·주석 | AO 명령선 단선, 장치 전원 상실 시 동작과 마지막/안전 위치 지원 여부를 제조사에 추후 확인한다. 확인 결과에 따라 감시·대응 기능 적용 여부를 결정한다. 지금 지원된다고 가정해 구현하지 않는다. |

### 5.3 Belimo 자료로 확인한 범위

- 아날로그 명령과 BACnet/Modbus 피드백을 함께 쓰는 Hybrid 모드는 지원한다(5~6쪽).
- 유량 제어에서는 목표 유량에 맞게 밸브가 자체적으로 개도를 조절한다(3~4쪽). 따라서 네 밸브에 같은 명령을 주어도 실제 개도는 서로 다를 수 있다.
- 통합 온도센서는 장치 위치의 물 온도 한 점이다(2·4쪽). 실제 환수측 설치를 확인하기 전에는 냉수 출구 온도라고 확정하지 않는다. 입·출수 두 점이나 냉수 ΔT가 모두 확보되는 것은 아니다.
- 유량센서 고장 시 장치가 유량 제어에서 위치 제어로 전환하고, 고장 해소 후 원래 설정으로 복귀한다(11쪽). DDC가 추가로 같은 전환을 명령해야 한다고 가정하지 않는다.
- Assistant에서 오류 정보를 읽을 수 있다는 설명은 있으나, RS485 오류 레지스터·전체 코드표는 이 데이터시트에 없다. 별도 Modbus/BACnet 인터페이스 설명서가 필요하다.
- 전원 상실과 통신선 단선은 ‘응답 없음’만으로 원인을 구분할 수 없다. 전원이 없는 장치를 DDC 코드로 움직일 수 있다고 가정하지 않는다.
- QTS 120행의 마지막/안전 위치 요구는 팬 정지 때 무조건 유지하라는 명시 지시가 아니다. P-11 확인 전 충족 완료라고 기록하지 않는다.

**구현 전 반드시 확인할 연결:** 기존 PICV 알람의 ‘명령값−실제 개도율’ 편차 판정은 위치 명령을 전제로 한다. 유량 제어 모드에서는 두 값의 물리적 의미가 달라 그대로 적용할 수 없다. 실제 모드를 확인하고, 알람 비교 대상을 정해야 한다. 이 문서에서 새 편차 기준·허용시간·유량 기준을 임의로 확정하지 않는다. 기존 저유량·패싱 기준도 밸브별 유량과 단위에 맞는지 확인한다.

## 6. 코드 작성 규칙과 주석

### 6.1 리더 지침의 적용

| 항목 | 적용 기준 |
|---|---|
| 변수 | `snake_case` |
| Boolean 변수 | `b` 접두어와 snake_case를 함께 적용하는 표기로 `b_...`를 사용한다. 리더 문서의 `bFan_ON` 예시는 snake_case와 혼재하므로 이 표기는 구현 시 통일하는 선택이다. |
| 가상 관제점 | 이름 앞에 `VP_` 사용. 실제 IO/통신 측정점을 이유 없이 VP로 바꾸지 않는다. |
| 상수 | 대문자, 단어는 밑줄로 구분 |
| Timer / LOOP2 ID | 숫자를 호출부에 반복하지 않고 용도를 알 수 있는 상수로 선언 |
| 작성 이력 | LJH가 수정한 로직 범위에 실제 작성일과 S/E 표기. 기존 JSY 작성 이력은 보존하고 전체 원저자를 LJH로 바꾸지 않는다. 날짜 예시는 `LJH[2026.1117]...: S ----` 형식이다. 실제 작성일이 달라지면 바꾼다. |

리더 문서에는 파일 단위로 작성자가 나뉘면 당장은 S/E 생략이 가능하다고 되어 있으나, 이번 작업에서는 LJH 변경 구간을 추적할 수 있게 표기하는 방향을 사용한다. 가독성을 위해 한 줄마다 붙이지 않고 의미 있는 블록 단위로 표시한다.

기존 관제점 이름·ID는 XML과 외부맵의 연결 키이므로 Python 변수명 정리와 구분한다. 이름 변경이 필요하면 모든 참조와 HMI/BMS 맵을 함께 수정한다. 이름을 예쁘게 바꾸기 위해 외부 연결을 끊지 않는다.

### 6.2 주석의 내용과 말투

- 동료가 다음 작업을 할 때 필요한 내용만 짧고 구체적으로 쓴다.
- 지금 동작을 택한 기술적 이유, 미확인 하드웨어 조건, HMI 입력 조건, 시운전 확인사항, QTS와의 차이를 남긴다.
- ‘프로젝트 리더 요청’, ‘사용자 승인’, ‘AI 검토’, 대화 경과, 구현 단계 홍보 같은 설명은 코드에 넣지 않는다. 협의 이력은 이 문서와 작업 이력에 둔다.
- 코드가 이미 말하는 단순 대입·비교를 장황하게 다시 설명하지 않는다.
- 단위, 조건, 확인 대상이 분명한 문장으로 쓴다. 아직 확인하지 않은 동작을 사실처럼 쓰지 않는다.

향후 코드에 사용할 수 있는 주석 예시이며, 아래 내용이 이미 적용됐다는 뜻은 아니다.

```text
# 최소 속도는 30% 유지. QTS 기준 20% 적용 전 팬 개발팀에 저속 운전 가능 여부 확인.
# ΔT 목표 -2℃는 SMX01 값 임시 사용. 냉방 시 RAT-SAT가 양수이므로 목표값 재확인 필요.
# 수동 속도는 코드에서 범위를 제한하지 않음. HMI에서 정지 0과 최소~최대 운전 범위를 구분할 것.
# 접점 모순 알람 지연은 임시로 5초 적용. 액추에이터 시험 결과에 따라 조정.
# 상위에서 계산한 대표값을 받을 수도 있음. 이 경우 사용 개수를 1로 설정.
# AO 단선·전원 상실 시 밸브 동작은 제조사 확인 후 대응 로직 적용 여부 결정.
```

## 7. 관제점 및 연계 변경 계획

아래는 기능 단위 계획이다. 이름·ID·레지스터 주소를 아직 확정한 목록이 아니며 임의의 제조사 레지스터를 생성하지 않는다.

| 구분 | 필요한 구성 | 연결 확인 |
|---|---|---|
| 상위 통신 | 감시 사용 VP, 타임아웃 VP(30초), 기존 HB/Prev/알람/Reset | Initialization, SF, 외부 통신맵, HMI |
| 외부 센서 | 종류별 수신 10점 × 4종, 종류별 사용 개수, 기존 집계 PV/Valid, 해당 고장점 확장 | Initialization, Alarm-2 및 PV 소비자. 기존점을 재사용하면 순증은 40개보다 적음 |
| 댐퍼 | 위치 미확인 4점 + 신호 모순 4점, 지연 설정 2점(120초/5초) | SF/알람 배치, 기존 Failover와의 관계 |
| PICV | 개도·유량·온도 4세트, 밸브별 통신/고장 상태, 공통 AO 명령 | PICV, SF 정지 확인, Alarm-1/3, IO/Modbus 맵 |
| 팬 모델 | 고정 팬 수와 실제 팬별 입출력·고장 집계 | Initialization, SF, Alarm-1/3 및 정지 출력 |
